# 模型侧统一接入与最小上游修改

## 已实现的 Index 适配

`hub_adapter.py` 集中放置 TTD 集成逻辑；`api.py` 和 `webui.py` 只保留模型管理器选择、执行作用域、middleware 与生命周期连接点。官方 `indextts/infer_v2_5.py` 与 api 基线一致，不导入 Hub，不调整设备或推理算法。共享推理锁在 loader 返回的实例上包装其 infer 方法，API/UI 对这个实例的访问共用同一锁；不改类、不做进程全局 monkey patch。

官方 CPU/GPU 混合、自动分配和 offload 保持原样。设备信息仅作观察，任何改变原有设备分工的建议都须先取得人类确认。

执行作用域需要包住实际模型调用，而不只是 HTTP 收到/响应：Gradio 排队、流式生成和后台任务的执行结束时刻可能晚于入队接口返回。现有入口有直接回调连接点，保留少量明确调用优于扫描函数名或修改框架私有注册表。

## 演进目标：统一模型池 Runtime（尚未实现）

模型接入的是统一的模型池 Runtime。原 ttd-fastapi-utils 的可复用能力迁入 Runtime；它不再作为模型必须单独安装、初始化和理解的第二套插件。旧包在现有调用方迁移完成后退役，不为保留旧抽象而维持两套生命周期。

建议的职责分区（模块名为设计示意，不是已发布 API）：

- `runtime.lifecycle`：模型对象、真实执行作用域、资源授权、代次校验、终态对账和持久补报。吸收 SmartModel 合理的惰性加载能力，移除并行 TTL 管理权；托管模型由 Hub 统一决定资源生命周期。
- `runtime.integrations.fastapi` / `gradio`：授权上下文、错误转换、框架启动退出与真实回调边界。模型仅安装一个 runtime 集成入口。
- `runtime.health`：统一暴露服务进程可用、模型驻留、GPU 观测等状态。健康请求不加载模型。
- `runtime.audio`：吸收当前音频后处理、语速、响度和 preset 等工具。能力随 Runtime 提供，但是否启用及参数保持显式；不能因纳管而自动改变模型音频效果。
- `runtime.observability`：统一模型实例/请求身份与生命周期事件，替代每个模型单独初始化旧告警插件。告警规则在控制面统一管理，不保留旧 webhook 的重复报警源。

对接入方是一套 Runtime，对实现方仍有清晰模块边界。核心管理协议不依赖 Torch/FastAPI/音频库；框架和媒体依赖按需安装/加载，例如安装面可表达为 runtime[fastapi,audio]。非 Python 服务实现同一管理协议，不要求引入 Python 依赖。具体发行包名和接口在迁移实现时确定。

## 模型仓库只保留薄适配

新增 `ttd_adapter.py` / `ttd_entry.py` 等文件，声明模型如何构造、真正执行、等待计算结束以及释放资源。尽量直接调用官方 app factory、callback、loader 或插件接口；无法外部注入时，只在创建和执行边界做最小明确修改，不扫描修改框架私有注册表。

设备放置、CPU/GPU 混合与 offload 始终由官方实现或人类确认的方案决定。Runtime 不做通用 .cpu()、.cuda()、device_map 或精度改写。现有 SmartModel 的通用 .cpu() 卸载不继承到新 Runtime。取消能力由模型明确提供，不能把统一管理误当作任意共享模型都可以强制中断。

## 迁移次序

1. 在独立 Runtime 代码中统一生命周期、框架接入、健康与通用音频能力；明确唯一源码和发行来源。
2. Index 薄适配改为消费 Runtime，保留官方推理源码；验证 API/UI、音频参数合同、资源回收和错误行为。
3. 按当前实际调用方逐个迁移旧 ttd-fastapi-utils，必要的过渡兼容层只是迁移工具，不成为永久产品层。
4. 调用方迁移完成后停止旧包发布与维护，删除冗余实现和初始化配置。

以上是演进设计，不是本 PR 已实现/发布的 Runtime。当前没有删除旧包或切换依赖它的其他服务。

## 当前验证边界

本 PR 的 16 项适配及真实 FastAPI/SDK HTTP 测试通过，其中模型为 fixture。初始版本已有 3090 API/UI 与卸载/重新加载证据；恢复原生设备放置、改为适配层安装推理锁后的最新版本尚未重新做 GPU 部署验收。
